# Claude 모델 분업 루프

이 프로필은 기존 개발·집필 절차에 모델별 역할을 연결합니다. 기존 품질 기준, 중단 조건, 작가의 결정권, 브랜치·배포 권한을 그대로 따릅니다. 이 파일을 추가하거나 PR을 여는 것만으로 자동 실행이 시작되지는 않습니다.

## 역할과 호출

| 역할 | 모델 / 노력 | 맡기는 일 |
| --- | --- | --- |
| 메인 | opus / high | 목표·계획·영향도 판단, 작업 분배, 통합과 최종 판정 |
| explorer | sonnet / medium | 파일·계약·설정 위치와 근거 검색. 읽기만 수행 |
| worker | sonnet / medium | 범위가 명확한 편집, 테스트·빌드·실행. 지정 파일만 수정 |
| researcher | sonnet / medium | 공식 문서·레퍼런스·저장소 문서 조사. 읽기만 수행 |
| advisor | opus | 별도 Opus 호출로 접근법, 반복 실패, 완료 전 누락 검토 |

모델 이름은 Claude Code의 별칭입니다. 실제 버전은 설치·계정·조직 정책에 따라 달라집니다. 시작할 때 메인 헤더와 `/tasks`에서 실제 모델·effort를 확인하고 결과 기록에 남깁니다. 기존에 다른 모델로 고정된 에이전트는 임의로 바꾸지 않고 목록으로 보고합니다.

탐색·작업·조사 중 필요한 역할만 호출합니다. 파일 존재 확인이나 명령 한 번에 별도 에이전트를 띄우지 않습니다. 독립적인 읽기는 병렬화할 수 있지만 같은 파일에 대한 쓰기, 통합, 최종 검수는 순서대로 수행합니다. 한 번에 쓰는 작업자는 하나입니다.

메인과 advisor가 같은 Opus 모델이어도 별도의 상담 호출로 계획과 결과를 다시 검토할 수 있습니다. 작업량이 큰 탐색·편집·테스트는 Sonnet에 맡기고 Opus 상담은 아래 세 지점에 집중합니다.

## 메인의 advisor 상담

1. 큰 계획에 착수하기 전: 목표·제약·예상 변경·검증 방법이 맞는지 상담합니다.
2. 같은 오류가 두 번째 발생했을 때: 최초 실패와 재시도 출력, 바뀐 가설을 전달하고 원인 탐색 방향을 재검토합니다. 기존 최대 수정 횟수는 늘리지 않습니다.
3. 긴 작업을 완료한다고 보고하기 전: diff, 작업자 보고, 실패·미실행 검증, 브랜치·배포 상태를 검토합니다.

매 도구 호출, 매 파일, 단순 수정마다 advisor를 부르지 않습니다. 호출 시점은 모델의 판단이므로 위 지침은 호출 횟수를 기술적으로 강제하는 장치가 아닙니다. 각 상담의 질문·결론·반영 여부를 기존 루프 기록 또는 PR 본문에 짧게 남깁니다.

advisor는 호출된 대화 전체와 도구 결과를 읽습니다. 메인 상담이 모든 서브에이전트의 비공개 대화를 자동으로 합쳐 읽는다고 가정하지 않습니다. 메인은 작업자의 근거·실패 출력·수정 요약을 전달받아 상담에 포함합니다. 서브에이전트의 advisor 상속도 실제 지원 여부를 확인합니다.

## 위임 계약과 완료 근거

메인은 위임 전에 목표, 읽을 자료, 수정 허용 파일, 금지 범위, 통과 조건을 줍니다. 결과는 다음 형식으로 받습니다.

- 실제 모델 / effort와 작업 브랜치
- 확인한 파일·줄 또는 문서 절
- 변경 내용과 이유
- 실행한 명령·종료 상태·검증 결과
- 실행하지 못한 검증과 이유
- 남은 결함 / 다음 한 단계

작업자는 merge·배포·설정 확정·품질 기준 변경을 결정하지 않습니다. 메인은 보고와 diff를 대조합니다. advisor의 의견은 테스트·실제 화면·작가 승인·독립 검수를 대체하지 않습니다. 검증이 불가능하면 PASS를 만들지 않습니다.

반복 검수는 같은 검수자에게 결함 목록과 변경분만 이어서 맡깁니다. 최종 기록은 기존 규칙의 확정 시점에 갱신합니다. 사용량 제한이나 접근 불가를 같은 명령으로 계속 재시도하지 않습니다.

## 설정과 실행

프로젝트 `.claude/settings.json`에 `model: opus`, `effortLevel: high`, `advisorModel: opus`를 두고 역할 파일에는 `model: sonnet`, `effort: medium`을 지정합니다. 사용자 홈 설정은 고치지 않습니다. 최신 Claude Code에서 프로젝트 수준 `effortLevel`은 Opus 5.5에도 적용됩니다.

저장소 루트에서:

```bash
node scripts/claude-loop.mjs --check
node scripts/claude-loop.mjs --run
```

첫 명령은 모델을 호출하지 않고 설치·원격 저장소·브랜치·환경변수·기존 에이전트를 확인합니다. 두 번째는 이미 선택한 작업 브랜치에서 **한 바퀴**를 수행하는 Claude 세션을 시작합니다. main/master 또는 detached HEAD에서는 실행을 거부합니다. 연속 작업은 현재 세션의 다음 지시와 기존 루프의 중단 조건을 따릅니다. 예약 작업·데몬·GitHub Actions의 AI 실행을 새로 켜지 않습니다.

권한 모드나 로그인 설정은 자동으로 바꾸지 않습니다. Claude Code 설치와 Opus 사용 권한이 있는 환경에서 실행합니다. advisor도 Opus를 사용합니다. advisor가 지원되지 않으면 활성화됐다고 기록하지 말고 BLOCKED로 보고합니다. 계정의 사전 승인이 없는 추가 과금 동의를 자동으로 수락하지 않습니다.

`CLAUDE_CODE_DISABLE_ADVISOR_TOOL`, `DISABLE_TELEMETRY`, `CLAUDE_CODE_EFFORT_LEVEL`와 모델 강제 변수는 보고만 합니다. 실행을 방해하면 런처는 멈추며 삭제·unset·설정 수정을 하지 않습니다. 사용자·로컬·프로젝트 settings의 env 및 기본 shell 초기화 파일에 있는 해당 변수도 확인합니다. 조직 관리 설정·다른 shell·부모 프로세스의 전체 설정은 진단 범위 밖이므로 최종 적용값은 `/tasks`와 advisor 활성화 알림으로 확인합니다.

## 사용량

advisor는 대기 중 무료로 세션을 감시하는 프로세스가 아닙니다. 호출할 때마다 입력·출력 사용량이 생기고, 전체 대화를 읽는 advisor 입력은 상담 간 캐시를 재사용하지 않습니다. Opus advisor 사용량도 메인 사용량에 추가됩니다. 작업 전후 `/usage`를 비교하고, 사용량 제한·접근 권한 문제는 재시도하지 않고 보고합니다.

## 소설 루프 연결

- `loop/LOOP.md`와 `loop/config.md`의 상태·목표 화수·작가 메모·보류 원고 우선·수정 3회 제한을 유지한다. 목표 화수가 달성됐다고 목표를 임의로 올리지 않는다.
- 메인 Opus가 에피소드 목적, 인물의 이유, 장기 복선, 문체와 원고를 직접 담당한다.
- `continuity-reviewer` Sonnet은 이름·시각·TOKEN·설정·인과·반전 시점·형식의 사실 검수만 한다.
- 원고를 쓰지 않은 `editorial-reviewer` Opus / high가 별도로 장면 가시성·인과, 필수 통과 조건, 7개 품질 항목, 역검수를 확인한다. 저렴한 사실 검수가 이 독립 편집 검수를 대신하지 않는다.
- 자료 범위와 재검수는 `LOOP.md`의 "필수 통과 조건"과 "마스터피스 점수"를 따른다. 같은 검수자에게 수정분을 이어 보내고, 원고 전체를 매번 모든 에이전트에게 다시 읽히지 않는다.
- worker의 연출 구현과 동작 검사는 "웹 연출"·"연출 동작 검사" 범위 안에서 한다. 웹 수정이 금지된 세션은 그 지시를 우선한다.
- 작가가 승인하지 않은 설정을 확정하거나 settings/05 항목을 체크하지 않는다. 결과 확정 전에 요약·수치·변경 기록을 갱신하지 않는다.
- 새 Claude 프로필은 작업 브랜치에서 준비하고 PR로 보고하는 것이 기본이다. `config`의 '바로 공개'만으로 작업 중인 브랜치·다른 원고를 통째로 main에 병합하지 않는다. 해당 세션의 공개 권한·개별 diff 검수·기존 배포 검증이 확인될 때 메인만 공개를 수행한다.

## 원격 쓰기 확인

원격 쓰기 전에 실제 인증 계정이 `jbseo-commits`이고 대상 저장소가 현재 공식 저장소인지 확인한다. GitHub 연결이 여러 개이면 그 계정 연결을 선택한다. origin 경로만으로 실제 인증 계정을 확인했다고 주장하지 않는다. 사용자 홈의 기존 역할은 실행 시 진단 목록으로 확인하며 다른 모델 고정은 자동 수정하지 않는다.

## Codex와 공통 진행 화면

Codex 역할 설정·한 바퀴 실행·Claude/Codex 공통 대시보드는 [codex-loop.md](codex-loop.md)를 따른다. 기존 Claude 런처와 예약 작업은 자동으로 변경되지 않는다. 대시보드는 localhost의 별도 문서이며 게임·원고 웹 화면에는 삽입하지 않는다.
