# Gemini 체인 집필 지침

Gemini 앱(Gemini 4 Argon)에서 `gemini-text` 브랜치를 '코드 가져오기'로 읽고 체인 집필할 때 따르는 절차다. Gemini는 저장소에 쓰지 못한다. 원고는 채팅에 출력하고, 반영은 Claude/Codex가 `chain/current`에 커밋한다.

## 0. 시작 전 확인

- 웹 검색·브라우저·GitHub 페이지 열기 금지. 가져온 저장소 파일만 근거로 쓴다.
- `GEMINI-TEXT-STATUS.md`의 생성 시각·원본 SHA·마지막 본편 파일을 먼저 보고한다. 작가가 말한 최신 상태와 다르면 멈추고 다시 가져오기를 요청한다.
- 체인 범위는 작가가 시작 메시지에서 지정한다(예: 106→110). 지정이 없으면 `loop/CURRENT-LINE.md`의 다음 집필 번호부터 5화.
- `loop/config.md`의 목표 화수보다 뒤라도, 작가가 시작 메시지로 범위를 지정했으면 그 범위가 승인이다.

## 1. 전편 정독 (작가 지시: 모든 화를 읽고 쓴다)

아래 순서로 **전부** 읽는다. 요약으로 대신하지 않는다.

1. `AGENTS.md`, `docs/gemini-chain.md`(이 파일)
2. `loop/CURRENT-LINE.md` 전체(맨 위 최신 항목 우선), `loop/config.md` 작가 메모
3. `loop/LOOP.md` 1~7절, `loop/SCENE-VISIBILITY-GATE.md`
4. `settings/` 전체. 특히 `11-writing-direction.md` 16절, `12-characters.md`
5. 원고 전편을 독서 순서대로:
   - `manuscript/ep001.md` → `ep002.md` → `ep002-1.md` → `ep003.md` … 처럼 **본편 epNNN.md 다음에 epNNN-1, -2 …** 순서.
   - **86~90화는 `loop/held/ep086.md`~`ep090.md`**에 있다(보류 원고지만 91화 이후의 연속성 기준). 각 `-notes.md`도 읽는다.
   - 71~105화는 아직 main 미공개 체인 원고다. 연속성 기준으로 쓴다.
6. `loop/story-so-far.md`(70화까지 공식 요약. 원문과 다르면 원문 우선)
7. 직전 구간 기록: `planning/ep101-105-chain-writing-review.md`의 '다음 인계'와 '나머지 연출 설계'
8. 이번 구간 설계: `planning/epNNN-NNN-*.md`. 맨 끝 `[통합검수 보강]` 블록이 있으면 원래 설계보다 우선.
9. 반복 금지·고정 규칙: `loop/CURRENT-LINE.md` 3·4절과 각 구간 '반복 주의'.

정독 뒤 보고(원고 쓰기 전):
- 읽은 파일 수와 마지막 본편, 105화 마지막 장면 5줄
- 이번 구간 설계 핵심과 직전 인계(미해결 항목)
- **19~24화는 10-19 개고본이 최신이다.** 71~105화가 개고 전 사실(감사 자료·비밀 경계·호칭 등)을 회상하는 곳이 있으면 목록으로 보고
- 설정과 충돌해 작가 확인이 필요한 점(없으면 "없음")

## 2. 설계 → 작가 승인

화마다 LOOP.md 2절 형식(서사 목적·구체 사건·즉시 비용/이득·장면 3~6개·핵심 선택·마지막 문장 방향·(제안) 목록·구체물). 직전 3화와 목표·충돌·선택·결과가 겹치면 다시 설계. 작가가 "승인"하기 전에는 원고를 쓰지 않는다.

## 3. 한 화씩: 집필 → 검수 → 수정 → 인계

**집필**
- 첫 줄 `# 제N화. 제목`(제목에 숫자 금지), 공백 제외 3500~5500자
- 짧은 문단·대사 중심, 장면 전환 `***`, 시스템 문구 한 줄씩 `**굵게**`, 모노의 말 `〈…〉`
- 새 장면 3~5문장 안에 장소·인물 배치. 설명보다 사건. 철학 질문은 화당 하나
- 재등장 인물은 첫 대사 근처에서 이전 접점을 짧게 환기(16-2절)
- 정밀 수치는 화당 1~2개, 단위 붙는 수는 아라비아 숫자
- 서인→도윤 "도윤"/"도윤 씨"+존댓말("형" 금지, 199화 전용). 메시지 쓰고 지우기 금지(200화 전용). 도윤 원칙 연설 금지
- 출력: `manuscript/epNNN.md` 내용을 코드블록 하나로. 블록 밖엔 글자 수 한 줄

**검수(다음 메시지에서, 원고를 쓰지 않은 편집자 입장)**
- 가시성 6문항 PASS/CHANGES(원문 인용), 필수 8항목, 점수 6항목(장면 필연성·인물 진실성·문장·대사·주제 깊이·긴장과 여운) 각 1~10 근거 인용, 역검수, 반복 금지 위반
- 거슬리는 표현: 번역투, 상투구, 설명조, 같은 동작·어휘 에코, 서술자가 감정·침묵 뜻을 풀어 주는 문장, "~지 않았다" 부정 서술 과다를 원문 인용으로 지적
- 전 항목 8 이상·평균 9 이상·필수 전부 통과면 PASS

**수정** 지적만 고친 최종본 코드블록 + 전후 대조. 같은 화 수정은 최대 3회.

**인계 노트** `loop/held/epNNN-notes.md` 형식 코드블록: 요약 5줄, (제안) 설정, 다음 화로 넘길 상태, 쓴 동작·소품, 점수표. 머리에 "Gemini 자기검수 — 독립 검수 아님".

PASS 뒤 작가가 "다음"이라고 하면 N+1로 3번을 반복한다.

## 4. 구간 마무리

전체 연속성 검수(이름·호칭·날짜·장소·소유·숫자, 이월 항목, 설계 감정 곡선 대비), 다음 구간으로 넘길 질문, `CHANGELOG.md` 맨 위 한 줄 제안.

## 5. 저장소 반영

작가가 원고·노트를 Claude/Codex에 넘기면 `chain/current`에 `manuscript/epNNN.md`·`loop/held/epNNN-notes.md`로 커밋한다. AGENTS.md 기준 공개(main)에는 독립 사실·편집 검수와 연출 구현이 별도로 필요하다.
