# 제20화 실제 삽화·정보 연출 평가

메인이 실제 연결된 원화3장을 파일로 직접 열고, 최종r1 원고의400×900 Chromium 화면을 확인했다. VN 전용 자산은 평가 범위에 넣지 않았다. 아래 평가는 현재 그림이며 교체·생성·웹 코드 수정은 하지 않았다.

| 대상 | 적합성과 읽기 효과 | 한계·남은 문제 |
| --- | --- | --- |
| 문 앞 `ep20-door-web.webp` | 윤세라가 문고리를 잡고, 서인이 붕대 감긴 오른손으로 서류를 들며 강연우가 곁에 있다. 고백과 손목 부상·감사 진입이 연결된다. | 누가 윤세라/강연우인지는 앞선 인물 접점에 의존한다. 본문 대화의 관계와 그림의 옷·위치로 따라갈 수 있고 부상 손을 반대로 그린 오류는 보이지 않는다. |
| 감사 `ep20-box-web.webp` | 윤세라 맞은편 시점에서 빈 확인란과 공동주방 자료를 나란히 보게 한다. 실제 납품과 종이상의 보호를 견주는 장면에 맞는다. | 이미지 속 문서 글자·시각은 읽을 수 없어 정확한05:18/07:00/07:40이나 기존/신규 범주를 단독으로 설명하지는 못한다. 본문과 정보 그래픽이 그 관계를 명확히 한다. |

## 실제 확인 근거

- 원화3개 직접 보기와 디코딩 성공. 문 앞/옥상은1092×1440, 감사실은1122×1402이며 모바일에서 각각약443px/420px/443px 높이다. 연속 인물 초상이 아니라 고백·서류 충돌·돌봄의 서로 다른 순간이다.
- [문 앞](evidence/figure-1.png), [납품 비교](evidence/figure-2.png), [감사실](evidence/figure-3.png), [보호 범주](evidence/figure-4.png), [대기 목록](evidence/figure-5.png), [옥상](evidence/figure-6.png), [실제 화말 미리보기](evidence/graybutton-preview.png).
- 첫 대기 목록 캡처는 일시적인MEMORY20 연결 알림이 가려서 알림이 사라진 뒤 같은 그림을 다시 캡처했다. 이를 영구 배치 결함으로 판정하지 않았다.
- `pilot.html`의 오래된 정적 팝업에는 다른 문구가 있지만 실제 화면은 기존 `reader-scenes.js`의 교체 결과다. 실제 DOM·캡처의 내용으로 평가했다.
- [브라우저 기록](evidence/browser-verification.json): 원고 해시,6개figure,원화3개 디코딩,pageerror0,가로 넘침 없음과 미리보기 표시/닫힘 확인. 직접 `showSp` 호출을 자연 스크롤 검사로 포장하지 않았다.
