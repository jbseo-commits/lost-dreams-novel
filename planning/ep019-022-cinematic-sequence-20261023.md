# 19~22화 이해형 컷신 시퀀스 카드 — 2026-10-23

목표는 앞서 기획한 14개 장면의 공간·사건 이해를 살리면서, PR #122의 시네마틱 문법인 **공간·관계 → 관찰자의 시선 → 발견할 디테일 → 짧은 반응 → 실제 후속 행동**으로 연결하는 것이다. 원문은 그대로 두고 이미 읽은 문단 뒤에만 컷을 표시한다. 컷이 아직 읽지 않은 결과·선택·비밀을 앞당겨 보여 주지 않는다. 사용자 확정 범위는 19~22화이며 A/B 인물 후보는 작가 선택 요청이 아니라 이 제작의 내부 연속성 참고다.

## 공통 연속성

- 시퀀스 순서는 19 → 19-1 → 20 → 20-1 → 21 → 21-1 → 22 → 22-1이다. 웹 4:5와 VN 16:9는 각기 별도 생성하며 자르기 재사용을 하지 않는다.
- 19화의 서인 오른손목은 띠 아래 멍이 보인다. 19-1화 습격과 새벽 대기까지 띠와 오른손목 멍을 유지한다. 20화부터 띠가 사라지고 압박 붕대가 보인다. 이후 붕대/손 상태를 원문보다 앞서 회복시키지 않는다.
- 동부 27번은 차가운 청록 지도와 따뜻한 집 안의 창으로 표현하되, 불빛은 실제 집이 아닌 복제 화면임을 시각적으로 유지한다. B의 2,400가구와 A의 36가구를 같은 화면에서 우열·정답 색으로 단정하지 않는다.
- 참여자 4·승인자 4는 화면의 빈 좌석·접속 표시만 쓴다. 화면/서류/표지에는 생성된 글자·숫자 대신 흐린 선과 빈 칸을 사용한다.
- 21화 원문 시각은 목록 전환 1:34, 확인자 입력 1:33, 재통화 약속 1:39까지 7분이다. 뒤의 실제 재통화는 1:36이다. 그림에 숫자를 굽지 않고 컷은 해당 원문 beat 뒤에만 둔다.
- 22화 첫 복도 컷은 서인의 등장 문단 뒤에 둔다. 아버지와 아이가 먼저 있는 앞 문단의 그림에 서인을 앞당겨 넣지 않는다.

## 추가 POV 컷

네 POV는 별도 원화다. 같은 그림의 확대를 카메라 이동이라 부르지 않는다. 19 손목은 같은 원문 문단에서 wide→detail로 자동 전환하고, 버튼은 전체/세부를 다시 볼 때 쓴다. 자동 진행·skip은 detail 프레임을 건너뛰지 않으며, 움직임 줄이기에서는 detail을 바로 보여 준다. 전체 그림 보기 모달에서는 두 프레임을 순서대로 확인할 수 있다.

- `ep19-wrist-detail`: 19화 손목 띠·멍을 강연우의 시선 뒤에서 보여 주는 별도 VN 프레임과 웹 삽화.
- `ep19-home-life`: 2,400 창 지도 다음, 작은 생활 장면을 가까이 확인하는 POV.
- `ep21-call-transfer`: 강연우가 커피잔을 내려놓고 첫 병원 회선을 여는 짧은 반응·행동. 숫자는 이미지에 넣지 않는다.
- `ep22-compute-choice`: 진행 중인 공공 검사 11개 패널과 비어 있는 대기 4개 패널을 함께 보여 주는 목록 POV. corridor 컷에서는 아이 신발이 아직 보이지 않는다.

## 구현과 출고 검사

- 웹 컷은 `reader-sequence19-22.js`가 원문 문단에 정확 문자열이 있을 때만 `assets/sequence19-22/<id>-web.webp`를 해당 문단 뒤에 삽입한다.
- VN event cut은 `vn/episode-cutscenes.js`의 원문 beat/범위/지문 검증을 통과한 경우에만 `vn/assets/sequence19-22/<id>-vn.webp`를 요청한다. 본문·선택지·오디오·저장 좌표는 바꾸지 않는다.
- 390×844 및 400×844에서 얼굴·손목·지도·확인 칸이 텍스트 패널과 조작 UI에 가리지 않는지 확인한다. 데스크톱에서 4:5 웹·16:9 VN 원본 비율도 확인한다.
- VN 공개 빌드에서는 19~22화 ID가 메인 컷맵에 있어도 `DEMO_CHAPTER_IDS` 필터로 1~11화와 사이 이야기 7편의 18장 경계를 유지한다. notes 내부 검수 HTML은 공지로 치환되며 비공개 시퀀스 이미지는 오프라인 데모에 포함하지 않는다.
- 실제 원화의 MIME·치수·바이트·SHA-256 및 각 시도·선택 이유를 provenance에 기록한다. 입력 PNG는 보존하고 각 판형의 네이티브 치수로 WebP quality 96/method 6 인코딩한다.
