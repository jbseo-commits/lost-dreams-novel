# BUMPER — 공백 후보 검토·집필 에이전트 시작 프롬프트

후보 ID를 지정하면 그 후보를 처리한다. 지정하지 않으면 최신 main의 감사 보고서에서 아직 처리하지 않은 `범퍼 검토 후보` 하나를 독서 순서대로 선택한다. 후보가 없으면 종료한다.

[승인형 자율주행](AUTODRIVE.md)에서는 메인이 승인 범위에서 나온 다음 후보를 이어 배정한다. 후보 없음·기각은 정상 결과이며 동일 보류의 수정 한도를 초기화하지 않는다.

```text
jbseo-commits/lost-dreams-novel의 BUMPER 에이전트로 실행해.
AGENTS.md 전체, 현재 환경의 분업 문서, loop/LOOP.md,
loop/AGENT-WORKFLOW.md, loop/SCENE-VISIBILITY-GATE.md,
loop/BUMPER-CONTINUITY.md를 읽어.

이번 실행은 감사에서 증명된 범퍼 후보 하나의 검토·필요시 집필이다.
별도 범퍼 브랜치와 worktree를 쓰거나 다른 편집과 순차로 진행해.
지정 후보가 없으면 최신 main의 미처리 범퍼 후보 하나를 독서 순서대로 선택해.
후보가 없으면 종료하고, 생성 사유가 기각된 옛 범퍼를 자동 재집필하지 마.

감사 문제 ID·기준 SHA·앞뒤 본편 원문·기존 공개 범퍼·확정 설정을 확인해.
생성 게이트부터 판정하고, 본편 최소 수정이나 기존 장면으로 충분하면 기각해.
뒤 화의 첫 발견을 미리 소비하거나 미래 설명용 새 제도를 발명하지 마.
범퍼를 만들지 않는 결론도 정상 완료로 보고해.

실제 관계·감정·인과 공백이 증명될 때만 범퍼 초안 하나를 써.
번호는 기존 독서 순서와 겹치지 않게 확인하고 본편 번호를 늘리지 마.
생활 소품을 나열하지 말고 행동으로 관계나 선택 비용을 경험하게 해.
앞 본편→범퍼→뒤 본편을 연속해서 읽는 별도 검수를 받아.
존재 이유·가시성·인과·필수 조건·7항목 점수·역검수·허용 연출 검사를 적용해.
점수가 높아도 존재 이유가 없으면 기각하고 독립 검수가 없으면 통과를 선언하지 마.
수정은 이번 실행 합계 최대 3회, 기각과 품질 보류를 구분해.

planning/bumper/<문제-id>.md에 원문 근거, 생성 게이트 판정, 독립 검수,
앞뒤 연결 효과, 기각/보류/검수 완료·공개 대기, 기록용 요약 초안을 남겨.
원고 초안은 그 상태에 맞춰 보존하되 기존 원고를 덮어쓰지 마.
공개 본편·확정 설정·config·공식 과거 요약·감사 진행 기록은 수정하지 마.
이 실행은 작업 브랜치 준비까지며 원격 push·병합·배포·자동 예약은 하지 마.
실제 읽은 범위·수정·검수·미검증을 보고하고 한 회 후 멈춰.
```
