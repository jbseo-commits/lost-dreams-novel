# 자율 집필 루프 절차

한 번 실행할 때 **집필 → 검수 → 배포**를 한 화씩 수행합니다. 어떤 AI든 이 순서를 그대로 따르세요.
작업 규칙은 [AGENTS.md](../AGENTS.md), 설정값은 [config.md](config.md)에 있습니다.

## 0. 준비

1. `git pull --ff-only`로 최신 상태를 받습니다. 실패하면(충돌, 미커밋 변경) **아무것도 고치지 말고** `loop/log.md`에 이유만 적고 끝냅니다. 로그도 커밋할 수 없으면 보고만 합니다.
2. `loop/config.md`를 읽습니다.
   - 상태가 `정지`면 끝냅니다.
   - 목표 화수가 숫자이고 `manuscript/`의 마지막 화 번호가 그 이상이면 "목표 달성"을 보고하고 끝냅니다.
   - 종료 시각이 적혀 있고 현재 시각(KST)이 그 이후면 "종료 시각 지남"을 보고하고 끝냅니다. 로그는 남기지 않습니다.
3. `loop/held/`에 보류된 원고가 있으면 새 화 대신 **그 원고부터** 고쳐서 검수합니다.

## 1. 맥락 읽기

반드시 모두 읽습니다.

- `AGENTS.md`, `settings/` 전체, `loop/config.md`의 작가 메모
- `loop/story-so-far.md` (화별 요약과 인물/수치 연속성 표)
  - 파일이 없거나 마지막 화가 빠져 있으면, 빠진 화를 **원문으로 읽고** 요약을 먼저 채웁니다.
- 직전 3화 원문 전체
- `loop/log.md`의 최근 기록 3개

## 2. 설계

`settings/09-narrative-arc.md`의 6부 구조에서 이번 화의 위치를 정하고, 아래를 짧게 정합니다 (파일로 남기지 않아도 됩니다).

- 이번 화의 목적 한 줄 (서사에서 무엇이 한 걸음 나아가는가)
- 장면 3~6개
- 마지막 문장의 여운 (다음 화로 끌고 가는 힘)
- 새로 필요한 설정이 있다면 목록 (→ 모두 `(제안)`)
- 제21화 이후라면 이번 화에서 **실제로 벌어지는 사건과 즉시 발생하는 비용/이득**을 한 줄로 정합니다.
- 그 사건이 어느 계층의 선택을 유리하게 만들고 어느 계층에 비용을 넘기는지 확인합니다.
- 철학적 질문은 한 화에 하나 정도만 남깁니다. 질문보다 사건이 먼저입니다.

## 3. 집필

- 파일: `manuscript/epNNN.md`, 첫 줄 `# 제N화. 제목`
- 분량: config의 범위 (공백 제외)
- 문체: 1~10화와 같게. 짧은 문단, 대사 중심, 한 줄 한 문단.
- AI 시스템 화면 문구는 한 줄씩 `**굵게**`로 씁니다. 웹 리더가 이 줄을 시스템 화면으로 보여줍니다.
- 장면 전환은 `***` 한 줄.
- 앞 화의 장면이나 대사를 되짚을 때는 누가, 어디서, 무엇을 말했는지 `story-so-far.md`나 원문에서 확인합니다.

### 제21화 이후 페이스 원칙

1~20화의 빠른 추진력을 유지합니다. 설정과 철학이 깊어져도 원고가 논설처럼 느려지면 안 됩니다.

- 대략적인 감각은 **사건 70% → 선택 20% → 질문 10%**입니다. 문장 수를 기계적으로 맞추라는 뜻이 아니라, 독자가 먼저 '무슨 일이 벌어지고 있는가'를 따라가게 하라는 기준입니다.
- 세계관 설명은 독립된 강의처럼 넣지 않습니다. 누군가 TOKEN을 잃거나, 의료 검증이 밀리거나, 회사 AI 접근권이 끊기는 등 **행동의 결과** 안에서 필요한 만큼만 드러냅니다.
- 인물은 주제를 설명하기 위해 움직이지 않습니다. 자기 가족, 직위, 욕망, 공포, 관계 때문에 움직이고 그 충돌에서 주제가 나오게 합니다.
- 같은 철학적 논쟁을 서로 다른 인물이 반복하지 않습니다. 한 번 말한 질문은 다음에는 대사보다 **새로운 비용과 선택**으로 발전시킵니다.
- 특히 계층 설정은 설명보다 서로에게 영향을 주게 합니다. 한 계층에 좋은 결정이 다른 계층에 즉시 비용을 만들 수 있어야 합니다.
- 서인의 통찰은 '천재라서 맞힌다'고 요약하지 않습니다. AI에게 무엇을 물을지 압축하고, 무엇을 검증하지 않을지 선택하고, 제한된 TOKEN 속에서 직접 판단해 온 습관을 행동으로 반복해 보여 줍니다.


## 3-1. 연출 (pilot.html)

글이 초안 단계를 넘으면, 그 화의 핵심 순간 **하나**를 웹 연출로 만듭니다. 연출은 글을 설명하지 않고 글이 끝낸 곳에서 한 번 더 찌르는 역할입니다.

- 고치는 곳은 `pilot.html`의 아래 부분뿐입니다.
  - `MAX`를 이번 화 번호로 올림
  - 범퍼화(`ep025-1.md` 같은 `N-1화`)는 화 번호를 세지 않습니다. 다음 본편 번호는 마지막 **본편** 번호 + 1이고, 웹에 넣을 때만 `BUMP`에 `{25:['25-1']}`처럼 적고 `D['25-1']`을 추가합니다.
  - `D` 표에 이번 화 한 줄 추가: 색 두 개(`a`, `b`), `token`, `sync`, `ghost`, `hook`(그 화의 마지막 여운 문장), `sp`(세트피스 id), `at`(스크롤 몇 %에서 뜰지)
  - 세트피스 `<div class="setpiece" id="...">` 하나와 그 CSS, 필요하면 `runXxx()` 함수 하나
  - 필요하면 `sceneMarkup`의 장면 카드, `epAtmosphere`의 속삭임 문구
  - `KEY` 표에 이번 화 강조 대사 1~2줄 (아래 텍스트 연출 참고)
- 이미 있는 화의 연출, 공통 엔진(`openEp`, `render`, `observe`, `fire`, `showSp`, `closeSp`), 표지, 알림창 스타일은 고치지 않습니다.
- 세트피스는 기본으로 터치를 통과시킵니다. 버튼이 필요할 때만 `interactive`를 붙이고, 그 경우 반드시 닫는 버튼을 둡니다.
- 앞 화들과 같은 장치(숫자 카운트, 점 행렬, 경고창)를 반복하지 말고, 이번 화에만 어울리는 새 문법을 찾습니다.

### 텍스트 연출 (글을 쓸 때부터 함께 설계)

기준은 **마스터피스**입니다. 연출은 원고를 다 쓴 뒤 덧붙이는 장식이 아니라, 문장을 쓸 때부터 함께 생각합니다. 원칙은 하나입니다: **글은 가리지 않고, 이야기 속 시간과 의미만 독자가 몸으로 겪게 한다.**

- **멈춤**: 한 줄로 떨어진 `0.8초.`, `침묵.`, `1초.` 같은 문단은 그 시간만큼 선이 차오르고 다음 문단이 기다립니다(최대 1초). 인물이 기다리는 순간을 독자도 겪어야 할 때만 이렇게 씁니다. 남발하면 효과가 죽습니다.
- **강조 대사**: `KEY` 표에 적은 문단만 강조됩니다(문단 전체와 글자 하나까지 같아야 함). 그 화의 주제를 짊어진 대사 1~2줄만 고릅니다. `hook`과 같은 문장은 넣지 않습니다.
- **마지막 문단**은 자동으로 천천히 내려앉습니다. 그러니 마지막 줄은 여운이 남는 문장으로 씁니다.
- **팝업 품질 기준 (마스터피스)**: 팝업은 주제를 요약한 카드가 아니라 **그 장면을 그대로 재현**합니다. 원고에 나온 숫자·이름·시각·대사를 그대로 쓰고, 과정(쌓임) → 절정(전환) → 결과(남는 것) 순서로 움직입니다. 예: 16화 `pathburn`(경로 폭증·연산량 급등·추천 경로 선택), 2화 `adwake`(광고 바다 → 종료 버튼 → 03:17 · -4.2 TOKEN), 14화 `leakclock`(사람을 격리해도 같은 간격으로 오르는 노출량 → 규정 준수 미러). 원고에 없는 사실은 만들지 않습니다. 기준 문장은 장면이 실제로 일어나는 문단에 둡니다. 여러 단계를 JS로 움직일 때는 `mkClock()`의 `at(ms, fn)`으로 일정을 잡으면 배속이 자동으로 걸립니다. 줄마다 차례로 나타나는 구성은 JS 없이 HTML 속성으로 씁니다: `data-t`(등장), `data-p`(도장), `data-g`(강조), `data-k`(취소선), `data-d`(흐려짐), `data-o`(사라짐)에 초를 적으면 됩니다. 공통 부품은 `.sc`, `.sc-row`, `.sc-card`, `.sc-q`, `.sc-stamp`입니다.
- **팝업 배속**: 떠 있는 팝업은 누르면 8배속으로 끝까지 가고 다시 누르면 닫힙니다. 숫자·경로를 JS로 움직이는 연출은 `state.ff`에 마지막 장면으로 바로 가는 함수를 등록합니다.
- **팝업 추가(`more`)**: 한 화에 팝업이 둘 이상 필요하면 `D[n].more=[{sp, on, w, ms}]`로 더합니다. 다른 팝업이 떠 있으면 기다렸다가 뜹니다.
- **시스템 문구**(`**굵게**`, 여러 줄 가능)는 기계의 목소리입니다. 사람의 말과 섞지 않습니다.
- 새 장치를 만들 때는 그 장치가 이야기에서 무슨 뜻인지 한 문장으로 말할 수 있어야 합니다. 말할 수 없으면 만들지 않습니다.
- 가독성이 먼저입니다: 빨리 넘기는 독자는 기다리지 않게 하고, 밝은 화면(8화처럼)에서도 글자가 보이는지 확인합니다.

## 4. 검수

기준은 **마스터피스**입니다. 잘 쓴 웹소설이 아니라, 이 작품이 끝났을 때 이 화가 빠지면 안 되는 화여야 합니다.

집필과 **분리해서** 합니다. 반드시 별도의 검수 에이전트(서브에이전트)에게 원고를 쓰지 않은 편집자의 눈으로 보게 하세요. 검수자는 칭찬보다 결함을 찾는 것이 임무입니다.

검수 전에 `git pull --ff-only`로 다시 받습니다. 그사이 `settings/`가 바뀌었으면 원고를 새 기준으로 먼저 확인합니다.

검수자에게 주는 자료는 아래로 한정합니다. 토큰을 아끼기 위해서입니다.

- 이번 화 원고 전문과 직전 3화 원문
- `loop/story-so-far.md`, `settings/` 전체, 이 4단계 표
- 연출 변경분(`git diff pilot.html`)
- 직전 3화보다 앞선 화는 통째로 읽히지 않습니다. 연속성 확인이 필요하면 그 장면만 검색해서 봅니다.

### 4-2. 마스터피스 점수 (각 1~10, 근거 문장을 원고에서 인용)

| 항목 | 10점의 모습 |

- **모든 항목 8점 이상, 평균 9점 이상**이어야 통과입니다.
- 미달이면 검수자가 짚은 결함을 고친 뒤 다시 검수합니다. 최대 3번까지 고칩니다. 부분 수정으로 안 되면 장면을 통째로 다시 씁니다.
- 재검수 방식은 `config.md`의 `재검수` 값을 따릅니다. 이 규칙이 예약 작업 프롬프트의 "처음부터 다시 검수"보다 우선합니다.
  - `고친 부분만`: 첫 검수를 한 **같은 검수자에게 이어서**(SendMessage 등) 지난 결함 목록, 고친 문장의 전후, 바뀐 연출 변경분만 보냅니다. 검수자는 결함이 해결됐는지 확인하고, 바뀐 부분에서 새 결함과 통과 조건을 다시 본 뒤 7개 점수를 다시 매깁니다. 같은 검수자를 이어 쓸 수 없으면(새 실행 등) 새 검수자에게 이번 화 원고 전문, 지난 검수 보고서, 바뀐 부분만 줍니다.
  - `처음부터`: 매번 새 검수자에게 위 자료 전체를 다시 줍니다.

### 4-3. 연출 동작 검사 (브라우저로 실제 확인)

저장소의 `.claude/launch.json`에 있는 `lost-dreams-novel` 미리보기 서버(`node scripts/serve.mjs`, 포트 5212)를 띄우고, 브라우저 창을 휴대폰 크기(약 400×900)로 맞춰 확인합니다.

1. `pilot.html` 표지의 "제1화 읽기"가 눌려서 1화가 열린다.
2. `pilot.html#ep{이번 화}`가 열리고 본문이 보인다.
3. 이번 화 `KEY` 대사가 강조되고, 멈춤 문단이 있으면 선이 차오른 뒤 다음 문단이 뜬다. 본문에 `**`가 그대로 보이지 않는다.
4. 스크롤하면 이번 화 세트피스가 뜨고, 닫히거나(자동/버튼) 사라진 뒤 **본문 버튼과 링크가 다시 눌린다**.
5. 콘솔 오류가 없다.
6. `index.html`의 원고 목록에 이번 화가 보인다.

하나라도 실패하면 고칩니다. 2번 고쳐도 안 되면 `pilot.html` 변경만 되돌리고(`git checkout pilot.html`) 글만 공개하며, 로그에 "연출 보류"로 남깁니다.

미리보기 창이 가려져 애니메이션이나 스크롤 이벤트가 멈추면, 스크롤 이벤트를 직접 보내거나 애니메이션 시점을 고정해 코드에서 확인합니다. 화면 캡처용 도구를 따로 만들지 않습니다.

### 4-4. 보류

- 4-1을 3번 고쳐도 못 맞추거나, 4-2를 3번 고쳐도 기준에 못 미치면 공개하지 않습니다. 원고를 `loop/held/epNNN.md`로 옮기고, 남은 결함과 마지막 점수를 `loop/log.md`에 적은 뒤 커밋하고 끝냅니다.

## 5. 기록 갱신

기록은 검수를 통과한 뒤에만 고칩니다. 보류되면 `loop/log.md`만 남깁니다.

- `loop/story-so-far.md`: 이번 화 요약 3~5줄, 새 인물과 바뀐 수치
- `settings/05-open-questions.md`: 새로 만든 설정을 `## 자율 루프 제안` 아래에 `- [ ] ... (제안, 제N화)`로 추가
- `CHANGELOG.md`: 맨 위 한 줄 (`- 날짜 · 자율 루프 · 제N화 「제목」 추가, 검수 통과`)
- `loop/log.md`: 맨 위에 아래 형식으로 추가

```
## 날짜 시각 · 제N화 「제목」
- 결과: 공개 / 보류 / 건너뜀(이유)
- 분량: 공백 제외 N자
- 검수: 통과 조건 결과, 마스터피스 점수 7개와 평균, 고친 횟수
- 연출: 세트피스 id와 한 줄 설명 / 연출 보류(이유)
- 새 제안: 몇 개 (요약)
- 배포: 성공 / 실패 (확인한 주소)
```

## 6. 배포

1. `node scripts/build-manifest.mjs`로 목록이 제대로 만들어지는지 확인합니다. (manifest.json은 커밋하지 않습니다.)
2. 커밋 메시지: `원고: 제N화 「제목」 (자율 루프)`
3. `git push`. 실패하면 `git pull --rebase` 후 한 번만 다시 시도합니다. 그래도 실패하면 로그에 적고 끝냅니다.
4. GitHub Actions의 "웹 배포"가 성공했는지 확인하고, `https://jbseo-commits.github.io/lost-dreams-novel/manuscript/epNNN.md`가 열리는지 확인합니다.
5. 배포 결과를 `loop/log.md`에 반영해야 하면 작은 커밋 하나로 올립니다.
