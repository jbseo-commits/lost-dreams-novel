# 승인 후 자율주행

작가가 실행 계획을 승인하면 메인이 FORWARD / READER AUDIT / BUMPER를 반복 진행한다. 역할·품질 기준은 [세 에이전트 협업 규칙](AGENT-WORKFLOW.md)과 [집필 루프](LOOP.md)를 따른다. 독립 역할의 한 회 프롬프트는 작업 단위이며, 승인된 자율주행에서는 메인이 다음 단위를 이어 맡긴다.

이 절차는 실행 중인 채팅/에이전트 세션의 진행 규칙이다. 문서 추가만으로 실행되지 않으며, 세션 종료 뒤 계속 도는 예약 작업이나 상시 프로세스를 설치하지 않는다.

## 1. 진입과 준비

`자율집필 시작해`, `자율주행 준비해` 등의 요청을 받으면 현재 세션의 기존 승인을 먼저 확인한다. 유효한 승인이 없으면 아래 준비를 마친 뒤 구체적인 계획을 제시하고 승인 대기한다. 이 절차를 넣어 달라는 요청은 실제 집필 시작 승인으로 간주하지 않는다.

준비할 것:

- 최신 main SHA, 공개 본편의 마지막 번호, 기존 초안·보류 원고 상태
- 실제 사용 가능한 에이전트·모델·검수·브라우저·원격 쓰기 도구
- 역할별 작업 브랜치/worktree와 쓰기 충돌 방지 방법
- FORWARD가 이번 화를 쓰려면 해결해야 하는 현재의 설정·인과 충돌
- 감사 진행 위치와 범퍼 후보 상태
- `config.md`의 상태·목표·종료 시각(KST), 작가 메모

준비 중에는 원문 읽기·계획·로컬 작업 공간 준비를 할 수 있다. 미승인 원고 집필·공개·배포는 시작하지 않는다. 도구나 현재 사건의 충돌이 실행을 막으면 먼저 그 사실과 필요한 결정을 제시한다.

## 2. 승인할 계획

계획은 `planning/autodrive/<실행-id>.md`에 남기고 채팅에도 요약한다. 실행-id는 날짜와 구분자로 충돌 없이 정한다. 최소한 다음을 포함한다.

실행 ID는 메인이 직접 생성하는 기록 식별자다. 작가에게 승인 ID를 입력시키거나 push마다 새 승인 번호를 받는 절차가 아니다.

| 항목 | 계획에 명시할 내용 |
| --- | --- |
| 본편 | 시작 번호, 마지막 목표 번호, 회당 1화, 기존 품질 보류 처리 |
| 독자 감사 | 첫 실행은 1화부터, 재개라면 기록된 다음 위치, 마지막 감사 대상, 회당 본편 5화와 공개 범퍼 |
| 범퍼 | 감사 후보만 검토, 회당 후보 1개, 승인된 감사 범위에서 나온 후보만 처리 |
| 종료 | 목표·감사/후보 범위·최대 회수 또는 종료 시각, config 정지, 작가 중단 |
| 반영 권한 | 로컬 준비 / 작업 브랜치 push / 검수 통과 변경의 main 반영 / 웹 배포 각각 허용 여부 |
| 동시성 | 실제 작업 공간과 도구 제한, 같은 checkout 쓰기 직렬화, 독립 검수 유지 |
| 제외 | 기존 공개 본편 리라이트·확정 설정 변경·목표 확대·예약 실행 등 승인하지 않는 범위 |

목표나 끝시각 없이 무한 실행을 계획하지 않는다. config 목표를 사용할 때도 실제 값을 읽어 계획에 적는다. config의 '바로 공개'만으로 main 반영 권한을 추정하지 않는다. 본편 목표 도달 뒤 감사/범퍼를 어디까지 마칠지도 계획에 명시한다.

작가는 제시된 계획에 대해 `승인, 자율주행 시작` 또는 동등한 뜻의 명시적 응답으로 승인할 수 있다. 고정 암구호가 아니다. 승인 전에는 기다리고, 시간 경과·무응답·다른 문서 수정 요청을 승인으로 취급하지 않는다. 승인된 범위와 대화의 승인 근거를 실행 기록에 남기되 파일에 '승인'이 적혔다는 사실만으로 대화 승인을 만들어내지 않는다.

승인된 반영 범위는 메인이 보존하고 각 역할에 전달한다. 같은 저장소·허용 브랜치·작업 범위의 commit·push·병합·배포마다 작가 승인·아이디·승인 번호를 다시 요구하지 않는다. 인증 계정·연결은 실행 시작 시 도구로 확인하고 변경이나 실제 인증 실패가 없으면 재사용한다. 플랫폼의 별도 실행 권한 요구는 작가 승인과 구분하며 임의로 우회하지 않는다.

## 3. 승인 후 반복

1. 승인 범위·config·최신 main·중단 요청을 확인한다.
2. FORWARD에 다음 본편 1화, READER AUDIT에 다음 독서 묶음을 맡긴다. 독립 읽기는 가능한 범위에서 병렬로 진행하고, 쓰기는 작업 공간 계약을 지킨다.
3. 감사 결과를 본편 수정 대상과 범퍼 후보로 나눈다. BUMPER는 후보 1개를 처리하며 후보 없음·기각도 정상 결과다.
4. 집필자의 자기 승인 없이 기존 사실·편집 검수를 수행한다. 가시성·인과·필수 조건·점수·역검수·허용 연출 검사를 유지한다.
5. 메인이 실제 diff와 검수 결과를 확인한다. 명시적으로 승인된 반영 권한 안에서 해당 변경만 순차로 반영한다. 공개 전 최신 main과 인접 화를 다시 확인하고 공식 기록을 갱신한다.
6. 회차 결과와 다음 위치를 기록하고, 승인 범위가 남고 해당 역할을 막는 조건이 없으면 다음 단위를 실행한다. 승인된 회차·개별 반영마다 다시 허락을 묻지 않는다.

공개 권한이 없는 FORWARD는 한 화를 준비한 뒤 `검수 완료·공개 대기`에서 멈춘다. 그 미공개 화를 공식 과거로 삼아 다음 번호를 계속 만들지 않는다. 감사와 후보 검토는 승인 범위 안에서 이어갈 수 있다.

## 4. 중단과 재개

- config 정지·승인 목표/끝시각 도달·작가의 `중단` 요청이면 해당 조건이 적용되는 작업을 멈춘다. 작가 중단 요청은 전체 실행에 적용한다.
- 설정 결정 필요, 현재 본편 인과 충돌, 독립 검수 불가, 쓰기 충돌, 필요한 반영 실패는 해당 역할을 `차단/결정 대기`로 남긴다. 영향 없는 감사는 승인 범위에서 계속할 수 있으나 같은 실패를 반복 호출하지 않는다.
- 같은 원고는 자율주행 전체에서 수정 합계 최대 3회다. 새 회차·재개·새 에이전트라는 이유로 횟수를 초기화하지 않는다. 한도 도달 원고는 보류하며, 새 근거나 작가 결정 또는 해당 보류의 재처리 지시 없이 다음 회차마다 다시 고치지 않는다.
- 미해결 감사 사항이 있다는 이유만으로 영향 없는 본편을 막지 않는다. 범퍼 후보 없음·기각은 전체 실행 실패가 아니다.
- 실제 세션/도구 제약으로 실행을 이어갈 수 없으면 진행 위치를 보존하고 `중단·재개 필요`로 보고한다. 백그라운드에서 실행 중이라고 주장하지 않는다.

각 회차 뒤와 중단 직전에 실행 기록을 갱신한다. 메인만 공통 기록을 쓰고 감사 에이전트만 감사 진행 기록을 쓴다.

- 승인 범위·승인 근거, 상태(승인 대기 / 실행 중 / 공개 대기 / 차단 / 중단 / 완료)
- 기준 main SHA, 실제 통합 커밋, 각 역할의 브랜치/worktree
- 본편 마지막 공개·초안/보류 번호·검수 결함·누적 수정 횟수
- 감사 완료·다음 위치, 후보 ID와 기각/미해결/공개 대기 상태
- 실제 검수·반영·배포 결과, 다음 한 단계

작가가 `자율주행 재개해`라고 하면 기록과 대화의 기존 승인, 최신 main·config·차단 해소 여부를 확인한다. 잔여 승인 범위라면 재승인 없이 이어간다. config 목표가 늘어도 승인 범위를 자동 확대하지 않는다. 새로운 설정 결정이나 권한·목표 확대가 필요할 때만 그 변경을 구체화해 추가 승인을 받는다.

## 시작

[승인형 자율주행 시작 프롬프트](autodrive-prompt.md)를 사용한다. 승인 없는 기본 역할 프롬프트와 로컬 CLI 런처는 계속 한 회만 수행한다. 이 절차가 런처를 상시 실행기로 바꾸지는 않는다.
